Lesson 3 · About 20 minutes

DIY: vibecode your first webpage

You will finish with a real webpage that has its own link. Anyone can open it, and it costs nothing.

  • Goal: build and publish one page

Before you start

  • A computer with a web browser
  • An email address, for a free GitHub account
  • A free AI chatbot from Popular Tools

0 of 10 steps done

Part 1: Make the page with AI

Tick each step as you go. Your progress is saved in this browser.

  1. Decide what your page is about

    Keep it small. One page about one thing: yourself, a hobby, a recipe, an event, a tiny game.

  2. Ask the AI to build it

    Open a free chatbot from Popular Tools. Copy this prompt and change the words in [brackets]:

    Prompt

    Build me a one-page website about [my dog Mochi]. Include [a short intro, three fun facts, and a list of her favorite things]. Make it look [playful and colorful] and work well on phones. Put everything (HTML, CSS, and JavaScript) in a single file called index.html. Do not use any outside images or libraries.

    Why one file? A single index.html is the easiest thing to publish. You only have one thing to copy.

  3. Look at it and ask for changes

    Most chatbots show a preview. Talk to the AI the way you would brief a designer:

    • “Make the title bigger and change the background to light blue.”
    • “Add a button that shows a random fun fact.”
    • “The text is hard to read on my phone. Fix it.”

    Repeat until you like it. This back-and-forth is vibecoding.

  4. Copy the final code

    When you are happy, send this so you get the whole page in one piece:

    Prompt

    Give me the complete, final index.html in one code block.

    Use the copy button on the code block. Keep the tab open.

Part 2: Put it online with GitHub

GitHub stores your file for free. A feature called GitHub Pages turns it into a live website.

  1. Create a free GitHub account

    Go to github.com/signup (opens in a new tab). Enter your email, a password and a username, then verify your email.

    Choose your username with care. It becomes part of your website's address.

  2. Create a repository

    A repository, or “repo,” is a folder for your project.

    1. Select the + in the top right corner, then New repository.
    2. Type a name with no spaces, such as my-first-site.
    3. Choose Public.
    4. Turn on Add a README file.
    5. Select Create repository.

  3. Add your page

    1. In your new repo, select Add file, then Create new file.
    2. Name the file exactly index.html, all lowercase.
    3. Select the large empty box and paste the code from the AI.
    4. Select the green Commit changes button, then Commit changes again in the pop-up. “Commit” means save.

  4. Turn on GitHub Pages

    1. Select the Settings tab at the top of your repo.
    2. Select Pages in the left sidebar.
    3. Under “Build and deployment,” set Source to Deploy from a branch.
    4. Under Branch, choose main and / (root), then select Save.

  5. Visit your live site

    Wait a minute or two, then refresh the Pages settings screen. Your link appears at the top and looks like this:

    https://your-username.github.io/my-first-site/

    Open it, then send it to someone.

  6. Make one improvement

    1. Ask the AI for a change, then ask for the complete index.html again.
    2. In your repo, open index.html and select the pencil icon to edit.
    3. Select everything, delete it, and paste the new code.
    4. Select Commit changes. Your live site updates in about a minute.

If something goes wrong

My link shows a “404” page

Wait a few minutes and refresh. If it still fails, check that the file is named exactly index.html, that it sits at the top level of the repo and not inside a folder, and that Pages is set to the main branch.

Pages is not available in Settings

On a free account the repo must be Public. In Settings, scroll to the bottom and change the visibility to Public.

My changes are not showing up

Give it a minute, then do a hard refresh: Ctrl + Shift + R on Windows, or Cmd + Shift + R on Mac.

The page looks broken or a button does nothing

That is a debugging problem, and the Tips lesson shows how to hand it to the AI.
